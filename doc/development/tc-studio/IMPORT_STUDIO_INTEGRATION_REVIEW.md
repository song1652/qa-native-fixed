# Import Studio를 TC 스튜디오에 통합하는 방안

> 2026-09-30 · **미구현 검토안**. 기능 비교·의존성·사용자 흐름을 세 에이전트가 독립 검토하고, 후속 라운드에서 통합 방법을 검토했습니다. 이번 논의에서는 기능을 삭제하거나 변경하지 않았습니다.

## 결론

**Import 기능은 TC 스튜디오에 통합할 수 있습니다.** 사용자에게는 TC 스튜디오의 ‘엑셀 가져오기’로 제공하고, 검증된 파일 반영·롤백 엔진은 공용으로 유지하는 방향을 권합니다.

최종 사용자 흐름은 다음과 같습니다.

**엑셀 가져오기 → 매핑·변경 내용 확인 → TC 라이브러리에 반영 → 수정·검토 → Excel 또는 Markdown 내보내기**

현재 새 작성 흐름은 동작하지만 기존 Import Studio의 모든 기능을 대체하지는 않습니다. 필요한 기능을 이전하고 검증한 뒤 별도 메뉴·화면을 제거합니다.

## 에이전트별 의견

| 관점 | 발견 | 의견 |
|---|---|---|
| 기능 비교 | 기존 매핑 프로필은 읽기만 가능. 원본 ID·태그와 행별 미리보기·가져오기 전체 롤백에 차이 | 기존 기능을 가져오기 영역에 보완한 뒤 통합 |
| 코드 의존성 | TC md 내보내기가 _import_commit·_import_validator와 기존 스냅샷 저장소를 사용 | 화면 제거와 공용 엔진 삭제를 분리 |
| 사용자 흐름 | 직접 Excel→md와 라이브러리→검토→md의 대상 조건이 다름 | 대상 개수·제외 이유·기존 자료 이전 방법을 명확히 제공 |

## 현재 대체된 기능과 남은 차이

| 기능 | 현재 TC 스튜디오 | 통합에 필요한 일 |
|---|---|---|
| 기준·임의 Excel 가져오기 | 자동/직접 매핑과 시트 선택 제공 | 기존 파일의 열 연결과 결과 비교 |
| 매핑 프로필 | 기존 프로필 조회·선택 | 새 프로필 저장·수정·삭제 |
| 원본 TC ID·태그 | 기존 프로필의 tc_id·tags를 사용하지 않음 | 원본 값 보존과 재가져오기 식별 규칙 |
| 상세 미리보기 | 시트별 개수·경고 | 행별 신규·갱신·동일·충돌·오류·제외 확인 |
| 다중 파일·시트별 매핑 | 한 파일·공통 매핑 | 필요 시 여러 파일 선택과 시트별 예외 매핑 |
| 라이브러리 가져오기 롤백 | 케이스 이력은 있으나 작업 전체 롤백 없음 | 템플릿·분류·케이스를 함께 복구할 가져오기 작업 기록 |
| md 미리보기·충돌·반영·롤백 | 공용 엔진으로 제공 | 기존 Excel Import 작업도 조회·복구할 경로 |
| 기존 작업 접근 | 기존 Import 화면/API가 담당 | TC 스튜디오의 가져오기 이력에 통합 |

## 권장 화면 구성

새로운 Studio 메뉴를 만들 필요는 없습니다. 기존 **엑셀 가져오기**를 다음 순서로 확장합니다.

1. **파일·시트 선택:** 파일과 대상 스위트를 고릅니다.
2. **열 매핑:** 기존 프로필 선택, 저장·수정·삭제, 원본 ID·태그·AUTO 연결을 제공합니다.
3. **변경 미리보기:** 행별 반영 내용과 제외 이유를 확인하고 충돌 처리 방법을 정합니다.
4. **가져오기 반영:** 변경 개수와 작업 식별자를 표시합니다.
5. **가져오기 이력:** 과거 작업 내용과 제외 목록을 보고 가능한 작업을 되돌립니다.

TC 내용 수정은 라이브러리에서, 파일 출력은 내보내기에서 진행합니다. 가져오기 중 사용자가 다시 같은 TC를 작성할 필요는 없어야 합니다.

## ID·태그 보존

현재 변환은 [프로필 변환 코드](../../../scripts/_tc_template.py)의 설명대로 tc_id·tags를 버립니다. 일반 외부 Excel을 그대로 이전했다고 말하려면 이 차이를 해결해야 합니다.

- 내부 case_id는 이력과 수정 연결을 위해 안정적으로 유지합니다.
- 외부 원본 ID와 태그는 별도로 보존합니다. 같은 원본의 같은 ID를 다시 가져올 때 기존 케이스와 연결하는 범위를 명확히 합니다.
- 이미 배정된 Markdown ID는 유지합니다. 원본 ID를 처음 연결할 때 기존 Markdown과 충돌하는지 미리보기로 확인합니다.
- 같은 원본 ID가 여러 행에 있으면 자동 덮어쓰지 않고 충돌로 표시합니다.
- 가져오기에서 태그가 손실되지 않도록 저장하고 내보내기 시 보존합니다.

## 자동화 대상 조건

모든 TC는 라이브러리에 가져올 수 있어야 합니다. Markdown 대상 조건은 현재의 Y(web)·승인·추정 문구/오류 없음·그룹 매핑 조건을 유지합니다.

AUTO 열이 없는 파일을 자동으로 전부 Y(web)으로 처리하지 않습니다. 사용자가 가져오기 단계에서 기본값을 명시적으로 고를 수 있게 하고, **가져온 수**와 **Markdown 대상 수**를 구분하여 제외 이유를 보여줍니다.

## 공용 엔진과 롤백 경계

[TC md 내보내기](../../../scripts/_tc_md_export.py)는 기존 [_import_commit](../../../scripts/_import_commit.py)의 미리보기·반영·롤백과 [_import_validator](../../../scripts/_import_validator.py)를 사용합니다. 엔진과 state/import_sessions·import_snapshots·import_profiles는 그대로 유지해야 합니다.

기존 Excel→md 작업과 TC→md 작업은 출처·종류를 표시해 같은 이력에서 찾도록 할 수 있습니다. 기존 작업은 현재 suite가 없는 경우가 있으므로 무조건 TC suite의 롤백 API로 전달하지 않습니다.

**Excel→라이브러리 롤백은 별도 저장 대상입니다.** cases만 되돌리면 덮어쓴 template.xlsx·template_profile.json이 남을 수 있습니다. 가져오기 전에 관련 자료를 함께 보관하고, 이후 편집이 있으면 충돌로 중단하며, 되돌리기를 새로운 이력으로 남기는 처리가 필요합니다.

## 구현 순서 제안

1. 기존 매핑 프로필 관리와 원본 값 보존을 TC 가져오기에 추가합니다.
2. 행별 미리보기·충돌 처리와 가져오기 작업 기록·복구를 추가합니다.
3. 기존 Import 작업의 조회·제외 목록·롤백을 TC의 이력 영역에 연결합니다.
4. 동일 파일로 구·신규 흐름의 ID·태그·내용·충돌·복구 결과를 비교합니다.
5. 기존 메뉴·전용 JS/CSS를 제거하고 /import-studio를 /tc-studio로 연결합니다.
6. 기존 /api/import 경로는 호환을 유지하고 사용처를 확인한 뒤 별도로 정리합니다.

화면 통합만 먼저 한다면 기존 직접 Excel→md 화면 요소를 TC 스튜디오의 고급 가져오기에 넣고 공용 API를 재사용하는 방법도 가능합니다. 다만 라이브러리 경유와 직접 파일 반영이 혼재하므로 임시 이전 수단으로 사용하고, 최종적으로는 하나의 작성·검토 흐름으로 모으는 편을 권합니다.

## 제거 전 수용 기준

- 매핑 프로필 저장·재사용·수정·삭제가 가능하다.
- 원본 ID·태그와 기존 Markdown 연결을 보존한다.
- 신규·갱신·동일·충돌·오류·제외를 확인할 수 있다.
- 반영 전 파일 변경 감지와 충돌 결정을 유지한다.
- 새로고침 후에도 과거 작업 조회·제외 목록·롤백이 가능하다.
- 라이브러리 가져오기 복구는 이후 사용자 편집을 덮어쓰지 않는다.
- 공용 엔진 테스트와 TC 내보내기 회귀가 유지된다.
- 기존 북마크의 이동 경로와 API 호환이 확보된다.

현재 검토는 코드 비교이며 위 수용 기준을 통과했다는 보고가 아닙니다.
