# Import Studio를 TC 스튜디오에 통합하는 방안

> 2026-09-30 · **통합 구현 반영**. 최초 에이전트 검토 뒤 사용자 승인으로 [통합 계획](plans/2026-09-30-import-integration.md)을 구현했습니다. 최종 테스트 수치와 실제 화면 증거는 [구현 보고](TC_AUTHORING_IMPLEMENTATION_REPORT.md)에 기록합니다.

## 결론

**Import 기능은 TC 스튜디오에 통합할 수 있습니다.** 사용자에게는 TC 스튜디오의 ‘엑셀 가져오기’로 제공하고, 검증된 파일 반영·롤백 엔진은 공용으로 유지하는 방향을 권합니다.

최종 사용자 흐름은 다음과 같습니다.

**엑셀 가져오기 → 매핑·변경 내용 확인 → TC 라이브러리에 반영 → 수정·검토 → Excel 또는 Markdown 내보내기**

TC 스튜디오 가져오기에 기존 기능을 보완하고 별도 Import 메뉴·전용 화면 자산을 제거했습니다. `/import-studio`는 `/tc-studio`로 이동하며 `/api/import/*`와 공용 엔진·저장 자료는 유지합니다.

## 최초 검토에서 확인한 차이

| 관점 | 발견 | 의견 |
|---|---|---|
| 기능 비교 | 기존 매핑 프로필은 읽기만 가능. 원본 ID·태그와 행별 미리보기·가져오기 전체 롤백에 차이 | 기존 기능을 가져오기 영역에 보완한 뒤 통합 |
| 코드 의존성 | TC md 내보내기가 _import_commit·_import_validator와 기존 스냅샷 저장소를 사용 | 화면 제거와 공용 엔진 삭제를 분리 |
| 사용자 흐름 | 직접 Excel→md와 라이브러리→검토→md의 대상 조건이 다름 | 대상 개수·제외 이유·기존 자료 이전 방법을 명확히 제공 |

## 구현된 통합 범위

| 기능 | 통합 구현 |
|---|---|
| 기준·임의 Excel | 자동/직접 매핑, 여러 파일 선택, 시트별 저장 프로필 선택 |
| 매핑 프로필 | 기존 프로필 읽기와 저장·수정·삭제. 기존 mappings 저장 형식 공유 |
| 원본 값 | source_tc_id·태그·대중소분류 보존 |
| 변경 미리보기 | 신규·갱신·동일·충돌·오류 및 변경 전후 내용. 화면에서 반영 전 필수 |
| 충돌 처리 | 건너뛰기 또는 라이브러리 값 갱신. 오류 행은 제외하거나 다시 작성 |
| 가져오기 복구 | 케이스·템플릿·프로필·분류·md 설정을 함께 보관·복구, 이후 편집 보호 |
| md 작업 이력 | 기존 Excel→md와 TC→md 목록·상세·제외 CSV·복구 |
| 기존 진입점 | 메뉴·전용 JS/CSS 제거, 기존 URL 이동, 기존 API 호환 유지 |

같은 이름의 시트를 여러 파일에서 동시에 가져오는 것은 지원하지 않습니다(`DUPLICATE_SHEET`). 선택을 나누거나 시트 이름을 구분해야 합니다. 시트별 프로필은 분석 가능한 파일의 특정 시트 매핑을 바꾸는 용도입니다. 최초 파일 분석 자체가 실패하면 공통 매핑을 먼저 맞춰야 합니다.

## 통합 화면 구성

기존 **엑셀 가져오기**에서 다음 순서로 작업합니다.

1. **파일·시트 선택:** 파일과 대상 스위트를 고릅니다.
2. **열 매핑:** 기존 프로필 선택, 저장·수정·삭제, 원본 ID·태그 연결을 제공합니다.
3. **변경 미리보기:** 행별 반영 내용과 제외 이유를 확인하고 충돌 처리 방법을 정합니다.
4. **가져오기 반영:** 변경 개수와 작업 식별자를 표시합니다.
5. **가져오기 이력:** 과거 작업 내용과 제외 목록을 보고 가능한 작업을 되돌립니다.

TC 내용 수정은 라이브러리에서, 파일 출력은 내보내기에서 진행합니다. 가져오기 중 사용자가 다시 같은 TC를 작성할 필요는 없어야 합니다.

## ID·태그 보존

[프로필 변환](../../../scripts/_tc_template.py)과 [가져오기 작업](../../../scripts/_tc_import_ops.py)은 원본 ID·태그를 보존합니다. 내부 case_id와 source_tc_id는 구분합니다. 같은 파일명·시트·원본 ID는 재가져오기 연결 기준이며 원본 ID가 없으면 출처 행을 사용합니다.

- 내부 case_id는 이력과 수정 연결을 위해 안정적으로 유지합니다.
- 외부 원본 ID와 태그는 별도로 보존합니다. 같은 원본의 같은 ID를 다시 가져올 때 기존 케이스와 연결하는 범위를 명확히 합니다.
- 이미 배정된 Markdown ID는 유지합니다. 원본 ID를 처음 연결할 때 기존 Markdown과 충돌하는지 미리보기로 확인합니다.
- 같은 원본 ID가 여러 행에 있으면 자동 덮어쓰지 않고 충돌로 표시합니다.
- 가져오기에서 태그가 손실되지 않도록 저장하고 내보내기 시 보존합니다.

## 자동화 대상 조건

모든 TC는 라이브러리에 가져올 수 있어야 합니다. Markdown 대상 조건은 현재의 승인·추정 문구/오류 없음·그룹 매핑 조건을 유지합니다.

자동화 여부를 별도 지정하지 않습니다. **가져온 수**와 **Markdown 대상 수**를 구분하고 승인·검증·문구 확인·그룹 연결에 따른 제외 이유를 보여줍니다.

## 공용 엔진과 롤백 경계

[TC md 내보내기](../../../scripts/_tc_md_export.py)는 기존 [_import_commit](../../../scripts/_import_commit.py)의 미리보기·반영·롤백과 [_import_validator](../../../scripts/_import_validator.py)를 사용합니다. 엔진과 state/import_sessions·import_snapshots·import_profiles는 그대로 유지해야 합니다.

기존 Excel→md 작업과 TC→md 작업은 출처·종류를 표시해 같은 이력에서 찾습니다. tc_library_suite가 있는 작업은 TC 전용 롤백으로 내보내기 기록을 함께 복원하고, 없는 작업은 공용 md 롤백을 사용합니다.

**Excel→라이브러리 롤백은 별도 저장 대상입니다.** cases만 되돌리면 덮어쓴 template.xlsx·template_profile.json이 남을 수 있습니다. 가져오기 전에 관련 자료를 함께 보관하고 이후 편집이 있으면 충돌로 중단하며, 되돌리기를 새로운 이력으로 남깁니다. 내구성 있는 작업 저널로 중단된 반영·복구를 이어갑니다.

## 직접 Excel→md와 통합 흐름의 차이

새 화면은 Excel을 라이브러리에 가져온 뒤 수정·검토하여 md로 내보냅니다. 가져온 전체 건수와 md 대상 건수는 다를 수 있습니다. 반려·추정 문구·검증 오류·그룹 미연결의 제외 이유는 내보내기 화면에서 확인합니다. 기존 직접 Excel→md API는 호환 목적으로 남아 있으며 새 화면에 별도 작성 흐름을 추가하지 않았습니다.

## 제거 전 수용 기준

- 매핑 프로필 저장·재사용·수정·삭제가 가능하다.
- 원본 ID·태그와 기존 Markdown 연결을 보존한다.
- 신규·갱신·동일·충돌·오류·제외를 확인할 수 있다.
- 반영 전 파일 변경 감지와 충돌 결정을 유지한다.
- 새로고침 후에도 과거 작업 조회·제외 목록·롤백이 가능하다.
- 라이브러리 가져오기 복구는 이후 사용자 편집을 덮어쓰지 않는다.
- 공용 엔진 테스트와 TC 내보내기 회귀가 유지된다.
- 기존 북마크의 이동 경로와 API 호환이 확보된다.
